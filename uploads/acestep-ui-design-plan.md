## 0. 핵심 요약

**한 줄 정의**: "Suno가 결과 자판기라면, 본 서비스는 음악을 가지고 노는 놀이터."

**핵심 차별화**:
- ACE-Step 1.5의 6가지 작업(text2music, cover, repaint, lego, extract, complete)을 일반인이 직관적으로 만질 수 있게 풀어냄
- Suno에는 절대 없는 "부분 수정"·"악기 추가/빼기"·"진화 트리" UX
- 한국어 자연어 입력 + 한국 콘텐츠 vertical 프리셋

**UI 철학**: Progressive Disclosure (점진적 공개)
- Spark (영감) → Play (놀이) → Master (마스터) 3단계
- 90% 사용자는 Play까지만 씀. 그래도 충분히 깊이 있음.

**기술 베이스**:
- ACE-Step 1.5 (MIT 라이선스, 상업 이용 자유)
- A100 2초 / RTX 3090 10초 / 4GB VRAM 최저
- 6가지 작업 + LoRA 학습 + 50+ 언어 지원

## 1. ACE-Step 1.5 정밀 분석

### 1.1 저자의 명시적 디자인 철학

레포의 튜토리얼 문서에서 ACE-Step 개발자(공준민)가 직접 밝힌 입장은 매우 분명하다.

> "이 모델은 '원클릭 생성'을 위해 설계된 것이 아니라, '인간 중심의 생성'을 위해 설계되었습니다."

그리고 Suno·Udio·MiniMax·Mureka 같은 폐쇄 플랫폼을 **직접적으로 비판**한다.

| 구분 | 원클릭 생성 (Suno 류) | 인간 중심 생성 (ACE-Step) |
|------|---------------------|---------------------------|
| 관계 | 고객-공급업체 | 협력자 |
| 게임 | 유한 게임 (결승선 있음) | 무한 게임 (놀이 자체가 목적) |
| 결과 | 비슷한 프롬프트 = 비슷한 결과 | 매 이터레이션이 다른 탐험 |
| 워크플로우 | 프롬프트 → 결과 | 씨앗 → 듣기 → 조정 → 반복 |
| 소유권 | 플랫폼 약관에 잠금 | 사용자 영구 소유 |

**UI 기획에 직결되는 함의**: ACE-Step의 강점을 살리려면 "결과 받기"가 아니라 **"탐험하기"의 UX**로 가야 한다. Suno 클론을 만드는 건 ACE-Step을 잘못 쓰는 것.

### 1.2 모델이 제공하는 6가지 작업 유형

이게 ACE-Step의 진짜 차별점이다. 일반 음악 도구에는 대부분 없는 기능들.

| 작업명 | 일반 사용자 표현 | 활용 시나리오 |
|--------|------------------|--------------|
| `text2music` | "글로 음악 만들기" | 새 곡을 처음부터 |
| `cover` | "이 노래를 다른 스타일로" | 발라드 → K-pop |
| `repaint` | "이 부분만 다시 만들기" | 후렴구만 더 신나게 |
| `lego` | "악기 추가하기" | 기타에 드럼 얹기 |
| `extract` | "악기 분리하기" | 보컬만 제거 |
| `complete` | "보컬에 반주 깔기" | 아카펠라 → 풀곡 |

**Suno는 text2music + 제한적 cover만 지원.** repaint/lego/extract/complete는 거의 없거나 매우 제한적. **이게 UI 차별화의 핵심 무기.**

### 1.3 모델의 두 뇌 (Two-Brain) 구조

```
사용자 입력 → [5Hz LM (기획자)] → 시맨틱 청사진 → [DiT (실행자)] → 오디오
                    ↓
              Chain-of-Thought:
              BPM·키·길이·캡션 자동 추론
```

**LM (Language Model) - 기획자 역할**:
- 사용자의 의도를 이해하고 음악 메타데이터 추론
- 캡션 자동 확장 (간단한 한 줄 → 풍부한 음악 설명)
- 가사·구조·악기 계획
- 4가지 옵션: 미사용 / 0.6B / 1.7B / 4B
- **중요**: 켜고/끌 수 있음 → "Simple Mode"는 LM 활용, "Pro Mode"는 사용자 통제

**DiT (Diffusion Transformer) - 실행자 역할**:
- LM 청사진을 받아서 실제 오디오 생성
- Turbo 모델: 8 스텝, 빠름, 일상용
- SFT 모델: 50 스텝, 디테일 풍부, CFG 지원
- Base 모델: extract/lego/complete 같은 특수 작업

**UI 설계에 직결**: 사용자는 LM/DiT 구분 절대 몰라야 함. 백엔드에서 자동 선택.

### 1.4 입력 제어 파라미터 (UI에 노출 결정 필요)

ACE-Step이 받는 모든 입력. 어느 것을 UI에 노출하고 어느 것을 숨길지 결정해야 함.

| 카테고리 | 파라미터 | 일반인 노출? | 비고 |
|---------|---------|------------|------|
| **작업 유형** | `task_type` | 간접 (버튼) | 6가지 작업 → 직관적 버튼 |
| **텍스트** | `caption` | ✅ 핵심 | 한국어 자연어 입력 |
|  | `lyrics` | △ (선택) | Master 모드만 |
| **메타데이터** | `bpm` | △ (Play 모드) | 슬라이더 |
|  | `keyscale` | ❌ Master | 일반인은 모름 |
|  | `timesignature` | ❌ Master | 일반인은 모름 |
|  | `vocal_language` | ✅ | 한국어/영어/없음 |
|  | `duration` | ✅ | 슬라이더 (15초~5분) |
| **오디오 참조** | `reference_audio` | △ (Play 모드) | 드래그&드롭 |
|  | `src_audio` | △ (Cover 시) | 자동 처리 |
|  | `audio_codes` | ❌ | 고급 사용자만 |
| **구간 제어** | `repainting_start/end` | ✅ (Repaint 시) | 파형 드래그 |

### 1.5 속도와 하드웨어

- A100에서 풀송 2초, RTX 3090에서 10초, 최저 4GB VRAM
- 배치 생성: 동시 8곡까지 가능
- 50+ 언어 지원 (한국어 포함)
- LoRA 학습: 8곡 + 1시간으로 자기 스타일 (12GB VRAM RTX 3090)
- VST3 플러그인 MVP 아키텍처 존재

**UI 설계 함의**:
- 빠른 속도 → **"기다림 없는 실시간 이터레이션 UI"** 가능 (Suno는 30~60초)
- 배치 생성 → **한 번에 4개 동시 결과** 제공 가능 (선택의 풍부함)
- LoRA → 장기적으로 **"내 스타일 만들기"** 기능

### 1.6 한계점 (솔직히)

- 학습 데이터 출처 완전 공개 X (Apache 2.0은 가중치 라이선스, 학습 데이터 합법성 별개)
- 품질: "Suno v4.5와 v5 사이" → Suno v5 따라잡진 못함
- 한국어 가창은 영어보다 자연스러움 떨어짐 (Week 1 PoC로 검증 필수)
- Gradio UI는 엔지니어 친화적, 일반인에겐 부담스러움
- VST3 플러그인은 아직 MVP 아키텍처 단계

## 2. UI 기획의 본질적 도전

ACE-Step의 모든 기능을 한 화면에 다 노출하면 일반인이 도망간다. 반대로 너무 단순화하면 ACE-Step의 진짜 가치(cover/repaint/lego)를 못 살린다.

### 2.1 벤치마크 비교

| 도구 | 진입 쉬움 | 결과 깊이 | 결론 |
|------|----------|----------|------|
| Suno | ⭐⭐⭐⭐⭐ | ⭐⭐ | 깊이 없음, 잠금 |
| ACE-Step Gradio | ⭐⭐ | ⭐⭐⭐⭐⭐ | 일반인 진입 불가 |
| **본 서비스 (목표)** | **⭐⭐⭐⭐⭐** | **⭐⭐⭐⭐⭐** | **양쪽 다 잡기** |

### 2.2 해결책: Progressive Disclosure

**원칙**: 처음엔 단 한 줄, 깊이 들어갈수록 강력해지는 UI.

**진입 곡선**:
```
숙련도 ↑
    │
    │              [Master Mode]
    │             /    (모든 파라미터)
    │            /
    │       [Play Mode]
    │      /   (변형/수정/추가)
    │     /
    │ [Spark Mode]
    │  (한 줄 입력)
    └────────────────────→ 시간
       0 ~ 5분  ~ 1시간  ~ 며칠
```

**90% 사용자는 Play까지만 씀.** 그래도 충분히 깊이 있음.
**10% 마니아는 Master까지 감.** 이들이 진성 유료 사용자.

## 3. 핵심 UI 컨셉: 음악 놀이터

### 3.1 3단계 모드 구조

#### Spark (영감) — 첫 5분

**목표**: 진입 장벽 0. 30초 안에 첫 결과 듣게 만들기.

- 입력: 한 줄만 가능 ("차분한 카페 음악")
- LM이 모든 메타데이터 자동 추론
- 결과: 4개 동시 생성 (배치 생성 활용)
- 듣기 → 좋아하는 거 ❤️ 선택 → Play 모드 진입

**ACE-Step 매핑**: Simple Mode + Batch Generation

#### Play (놀이) — 5분 ~ 1시간

**목표**: 사용자가 "빠져드는" 단계. 무한 게임 진입.

- 좋아한 곡에서 "변형" 옵션 제공
  - 🎨 "비슷한 분위기로 더" (cover + 같은 스타일)
  - 🎭 "다른 스타일로" (cover + 다른 스타일)
  - ✂️ "부분만 다시" (repaint)
  - 🎸 "악기 추가/빼기" (lego/extract)
- 각 변형은 부모 카드와 연결 → 진화 트리 형성
- 가사 입력은 선택 (없으면 인스트루멘탈)

**ACE-Step 매핑**: cover, repaint, lego, extract, complete 작업을 직관적 버튼으로

#### Master (마스터) — 깊이 있는 사용자

**목표**: 진성 유저가 ACE-Step의 모든 힘을 쓰게.

- BPM·키·박자·CFG·시프트 등 모든 파라미터 노출
- 가사 직접 입력 + 구조 태그 ([Verse], [Chorus], [Bridge])
- 레퍼런스 오디오 업로드 (음색 가이드)
- LoRA 학습 ("내 스타일 만들기")
- DAW Export (Logic Pro·Pro Tools 호환 stem)

**ACE-Step 매핑**: 모든 입력 파라미터 + LoRA Training + 고급 모드

### 3.2 핵심 메타포: "음악 카드"

생성된 곡 하나하나가 **카드**다. 단순한 곡 리스트가 아닌 트레이딩 카드 비주얼.

```
┌──────────────────────────────┐
│ 🎵 잔잔한 카페 어쿠스틱       │
│ ━━━━━━━━━━━━━━━━━━━━━━━━━━━ │
│ [파형 미니맵 + 재생 버튼]     │
│ ━━━━━━━━━━━━━━━━━━━━━━━━━━━ │
│ 🎸 어쿠스틱 기타  🥁 가벼운 드럼│
│ ♪ 92 BPM  C Major  3:24       │
│ ━━━━━━━━━━━━━━━━━━━━━━━━━━━ │
│ [변형] [부분 수정] [악기 +/-] │
└──────────────────────────────┘
```

**카드의 비밀**: 사용자가 만진 모든 곡이 "진화 트리(Family Tree)"로 연결됨.

```
🌱 첫 씨앗곡 (Spark 결과)
├── 🎵 변형 A (K-pop 스타일)
│   ├── 🎵 베이스 추가 버전
│   └── 🎵 후렴 부분 다시
└── 🎵 변형 B (재즈 스타일)
    └── 🎵 보컬 추가 버전
```

**왜 이게 강력한가**:
- Suno에 없는 UX → 명확한 차별화
- 사용자의 작업이 "쌓이는 자산"처럼 느껴짐 → 락인 효과
- ACE-Step의 cover/repaint/lego를 시각적으로 활용
- 공유 시 "내 진화 트리"를 자랑할 수 있음 → 바이럴

- 프리셋은 **한국 콘텐츠 vertical** 중심 (영상 BGM, 공부, 카페, 잠들기, 드라이브, 운동)
- 인기 음악 섹션은 마케팅 효과 + 사용 예시 동시 제공

- 4개 동시 생성 = ACE-Step의 batch 능력 활용. 사용자는 "이 중에 맘에 드는 거" 선택
- 좋아한 곡 ❤️ 표시 → 다음 변형의 기반
- "상세 컨트롤 펼치기"는 접혀있어서 일반인은 보지 못함

이게 핵심 차별화 기능이다.

│   ░░██████░░░░██████░░██████░░██████░░██░░     │

│           [드래그로 구간 선택]                  │

**여기서 마법이 일어남**: 파형 위에서 손가락으로 구간 드래그하고 "더 신나게" 한 줄 쓰면 30초만 다시 생성. 이건 Suno에 없다. **음악을 "그림처럼 편집"하는 경험.**

**기술적 매핑**: ACE-Step `repaint` 작업 + `repainting_start/end` 파라미터

## 6. 3개월 출시 로드맵

이전에 작성한 3개월 MVP 플랜에 ACE-Step UI 컨셉을 매핑한다.

### Month 1 (Week 1~4): Spark Mode

**핵심 기능**:
- 한 줄 입력 → 4개 동시 생성 → 듣고 다운로드
- ACE-Step Simple Mode 활용 (LM이 모든 메타데이터 추론)
- 빠른 시작 프리셋 6개 (한국 콘텐츠 vertical)
- 결제 + 한도 정책
- 한국어 자연어 → ACE-Step 캡션 변환 (Claude API)

**일부러 빼는 것**: 카드 진화 트리, 변형, 부분 수정, 악기 레이어, 라이브러리. 전부 Month 2~3.

**의도**: Suno 클론처럼 보일 수 있지만 **의도된 단순화**. 진입 장벽을 0으로 만들어서 우선 사용자 확보. 흐름이 만들어진 후 점점 깊이 추가.

**Week 1 PoC 핵심 질문**:
- ACE-Step 1.5가 한국 크리에이터 기준 "사용 가능한" 인스트루멘탈을 생성하는가? (30개 프롬프트, 5점 척도)
- Replicate에 ACE-Step 1.5가 올라가 있는가? 없으면 직접 모델 업로드 또는 자체 GPU 호스팅 필요

### Month 2 (Week 5~8): Play Mode 진입

**핵심 기능 추가**:
- 좋아한 곡 ❤️ 표시
- "비슷한 분위기로 더" 버튼 (cover 활용)
- "다른 스타일로" 버튼 (cover + 캡션 변경)
- 진화 트리 시각화 (간단한 부모-자식 관계만)
- 라이브러리 페이지

**이때 사용자 락인이 생긴다**. 자기 진화 트리가 쌓이는 게 자산처럼 느껴지므로.

**기술적 매핑**:
- cover 작업 호출 = 기존 곡을 `src_audio`로, 새 캡션 함께
- 진화 트리 = DB에 parent_id 필드만 추가하면 됨 (간단)

### Month 3 (Week 9~12): Repaint + Lego

**핵심 기능 추가**:
- 파형에서 구간 드래그 → 그 부분만 재생성 (repaint)
- 악기 추가/빼기 토글 UI (lego/extract)
- 영감 카드 (오디오 업로드 → 분위기 추출)
- 한국어 가사 직접 입력 + 구조 태그

이 시점에 다른 도구로 못 따라할 깊이가 생긴다. **Suno는 절대 안 따라온다** (이미 자기 UX에 갇혀있음).

**파형 드래그 UI 기술**:
- 라이브러리: WaveSurfer.js 또는 Tone.js
- API 호출: `task_type="repaint"`, `repainting_start`, `repainting_end`, 새 캡션

### Month 4+ (PMF 후): Master Mode

- 모든 파라미터 노출 (BPM, 키, 박자, CFG, 시프트)
- 레퍼런스 오디오 + LoRA 학습 ("내 스타일 만들기")
- 협업 기능 (진화 트리 공유)
- DAW Export (stem 분리 → Logic Pro·Pro Tools 호환)
- 가능하면 VST3 플러그인 (ACE-Step VST3 MVP 활용)

## 7. 핵심 결정사항 3가지

### 결정 1: ACE-Step를 어디서 돌릴 것인가?

| 옵션 | 시점 | 곡당 비용 | 콜드 스타트 | 운영 부담 |
|------|------|----------|------------|----------|
| **(a) Replicate API** | Month 1 즉시 | $0.10~0.30 | 5초+ | 매우 낮음 |
| **(b) FAL.ai 또는 자체 GPU 인스턴스** | Month 3~ | $0.05~0.15 | 가변 | 중간 |
| **(c) 자체 GPU 클러스터** | Month 6+ | $0.02~0.05 | 0 (warm) | 매우 높음 |

**추천**: Month 1에는 무조건 (a). Week 1에 Replicate에 ACE-Step 1.5가 올라가 있는지 확인 필수. 없으면 직접 모델 업로드 가능한지 알아봐야 함.

**Week 1 검증 액션**:
- Replicate 검색: "ACE-Step" 또는 "ace-step-1.5"
- 없으면 Hugging Face Spaces에서 데모 확인
- 자체 호스팅 옵션 평가: RunPod, Vast.ai

### 결정 2: 한국어 UI vs 영어 UI

**추천**: 한국어 우선 + 영어 즉시 전환 가능 (i18n 구조).

이유:
- ACE-Step UI가 이미 한국어 지원 → 추가 부담 적음
- 한국 vertical 집중이 wedge
- 글로벌 확장 가능성 닫지 않음

**구현**: Next.js `next-intl` 또는 `next-i18next` 사용

### 결정 3: 어디까지 진화 트리를 보여줄 것인가?

**추천**: Month 2까지는 **간단한 카드 그리드 + 부모 카드 표시만**. 풀 트리 시각화는 Month 4+ Master 모드에.

이유:
- 풀 트리는 D3.js 등 복잡한 시각화 필요 → 솔로로 시간 큼
- 일반인은 "내 곡 4개 → 변형 8개" 정도면 충분히 이해
- Master 모드에서 트리 비주얼이 핵심 가치 → 거기서 차별화

## 부록 A: ACE-Step API 호출 매핑

각 UI 액션이 ACE-Step의 어떤 호출에 대응하는지.

### A.1 Spark Mode (한 줄 입력 → 4개 곡)

```javascript
// 사용자 입력: "잔잔한 카페 음악"

// Step 1: 한국어 → 영문 캡션 변환 (Claude API)
const caption = await claude.translate(userInput);
// → "calm cafe acoustic music, soft guitar, gentle drums"

// Step 2: ACE-Step Simple Mode + Batch x4
const results = await aceStep.generate({
  task_type: "text2music",
  caption: caption,
  duration: 180,           // 3분 기본
  use_lm: true,            // LM 활용
  thinking_mode: true,     // CoT로 메타데이터 자동 추론
  batch_size: 4,           // 4곡 동시
  // bpm, key, time_signature 등은 LM이 자동 결정
});
```

### A.2 변형 (cover - 같은 분위기로 더)

```javascript
// 사용자: 곡 A를 ❤️ → "비슷한 분위기로 더" 클릭

const variant = await aceStep.generate({
  task_type: "cover",
  src_audio: songA.audio_url,
  caption: songA.caption,      // 같은 캡션 유지
  // 약간의 variation seed 추가
  seed: Math.random() * 10000,
});
```

### A.3 변형 (cover - 다른 스타일로)

```javascript
// 사용자: 곡 A → "K-pop 스타일로" 입력

const variant = await aceStep.generate({
  task_type: "cover",
  src_audio: songA.audio_url,
  caption: "upbeat K-pop, energetic vocals, synthesizer drums",
  // 멜로디 구조는 유지, 스타일만 변환
});
```

### A.4 부분 수정 (repaint)

```javascript
// 사용자: 곡 A의 0:45~1:15 구간 선택 + "더 신나는 후렴" 입력

const edited = await aceStep.generate({
  task_type: "repaint",
  src_audio: songA.audio_url,
  caption: songA.caption,
  repaint_caption: "energetic chorus with strong drums",
  repainting_start: 45,
  repainting_end: 75,
});
```

### A.5 악기 추가 (lego)

```javascript
// 사용자: 곡 A → "베이스 추가"

const layered = await aceStep.generate({
  task_type: "lego",
  src_audio: songA.audio_url,
  caption: "add bass guitar layer",
  // base 모델 필요 (turbo/sft는 지원 X)
  model: "acestep-v15-base",
});
```

### A.6 악기 제거 (extract)

```javascript
// 사용자: 곡 A → "보컬 빼기"

const instrumental = await aceStep.generate({
  task_type: "extract",
  src_audio: songA.audio_url,
  extract_target: "vocal",      // 또는 instrument_name
  model: "acestep-v15-base",
});
```

### A.7 오디오 이해 (영감 카드)

```javascript
// 사용자: 좋아하는 곡 업로드

const analysis = await aceStep.analyze({
  src_audio: uploadedFile,
});
// 반환: { bpm, key, time_signature, caption, instruments[], mood }

// 그 후 새 곡 생성에 reference_audio로 사용
const newSong = await aceStep.generate({
  task_type: "text2music",
  caption: userPrompt,
  reference_audio: uploadedFile,
});
```

## 부록 C: UX 인터랙션 세부

### C.1 Spark Mode 첫 사용 경험 (Onboarding)

**Step 1**: 랜딩 → 입력창 위에 placeholder 애니메이션
```
"어떤 음악을 만들고 싶으세요?"
"잔잔한 카페 음악..." (자동 타이핑)
"신나는 운동 음악..."
"집중할 때 듣는 BGM..."
```

**Step 2**: 사용자 입력 → "✨ 만드는 중..." (30초 로딩)
- 진행 바 + 재미있는 메시지 ("악기를 고르는 중...", "분위기를 잡는 중...")

**Step 3**: 4개 카드 동시 등장 → 자동으로 첫 곡 재생 시작
- 사용자가 다른 카드 클릭 시 즉시 전환
- 5초 후 "어떤 곡이 가장 마음에 드세요?" 툴팁

**Step 4**: ❤️ 클릭 시 → "더 만들기" 버튼 4개 등장 (변형 옵션)
- 첫 사용자에게 "이 버튼은 이런 일을 해요" 툴팁 1회

### C.2 Repaint 인터랙션

**파형 드래그**:
- 마우스 다운 → 시작점
- 드래그 → 끝점 (실시간 하이라이트)
- 마우스 업 → 구간 확정 + 입력창 등장

**제스처 디테일**:
- 최소 5초, 최대 60초 구간
- 핀치 줌으로 파형 확대 가능 (모바일)
- 더블 클릭 → 자동 구간 (해당 마디 또는 verse/chorus 단위)

### C.3 진화 트리 인터랙션

**작은 진화 표시** (Month 2):
- 곡 카드에 "← 부모곡" 작은 텍스트
- 클릭 시 부모곡으로 이동

**전체 트리 뷰** (Month 4+):
- D3.js 또는 React Flow로 시각화
- 줌/팬 가능
- 곡 클릭 → 미리듣기 패널 열림
- 가지 클릭 → 변형 종류 표시 (cover/repaint/lego)

### C.4 모바일 우선 디자인

**가정**: 한국 사용자 70%+ 모바일 접근.

- 모든 화면 모바일 우선 설계
- 파형 드래그는 터치 친화적 (최소 영역 44px)
- 4개 동시 카드 → 모바일은 세로 스크롤 1열, 데스크탑은 2x2 그리드
- 오디오 재생 컨트롤은 하단 고정 (mini player)

## 부록 D: 경쟁 분석 추가 노트

### D.1 Suno의 UI 약점 (우리가 노릴 곳)

- 곡 결과가 "리스트"로 쌓임 → 자기 작업 히스토리 시각화 약함
- 변형은 가능하지만 직관적이지 않음
- 부분 수정 불가 (Suno Studio는 별도 페이지에 복잡함)
- 한국어 UI 미흡 (영어 위주)
- 가격 비쌈 ($10/월, 한국 환율로 14,000원+)

### D.2 ACE-Step Gradio의 UI 약점 (우리가 개선할 곳)

- 모든 파라미터가 한 화면에 노출 → 일반인 도망
- 작업 유형(task_type) 선택이 드롭다운 → 직관적 X
- 결과가 단일 → 비교/선택 UX 없음
- 진화·역사 개념 없음 (한 번 생성하고 끝)

### D.3 Soundverse·Mubert·Beatoven의 차별점

- Soundverse: "DNA" 컨셉으로 브랜드 sonic identity 학습 → B2B 강함
- Mubert: 실시간 무한 스트림 + API 강점
- Beatoven: 영상 분석 → 자동 매칭 BGM

**본 서비스의 자리**: Soundverse만큼 깊지 않고, Mubert만큼 인프라 강하지 않고, Beatoven만큼 자동화 안 됨. 대신 **"가지고 노는 재미" + "진화 자산화"**가 유일한 강점.
